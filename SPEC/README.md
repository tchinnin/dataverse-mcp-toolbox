# SPEC Folder - Implementation Specifications

This folder contains comprehensive specifications, implementation guidelines, and architectural documentation for the Dataverse MCP Toolbox project. These documents are designed to guide AI-assisted development (GitHub Copilot) through the complete implementation process.

## Purpose

The SPEC folder serves as a knowledge base for coding agents to:
- Understand the project architecture and design decisions
- Follow consistent implementation patterns
- Document mechanisms and patterns as they are implemented
- Track implementation progress and decisions
- Ensure cross-platform compatibility (Windows/macOS)

## Contents

### Core Documentation

- **[TERMINOLOGY.md](TERMINOLOGY.md)** - Clarification of key terms (Plugin vs MCP Tool vs Toolbox)
- **[ARCHITECTURE.md](ARCHITECTURE.md)** - Detailed technical architecture, component design, and technology stack decisions
- **[PLUGIN_INTERFACES.md](PLUGIN_INTERFACES.md)** - Complete plugin development interface specifications and examples
- **[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)** - Step-by-step implementation roadmap and milestones
- **[CODING_GUIDELINES.md](CODING_GUIDELINES.md)** - Coding standards, patterns, and best practices for agents
- **[MECHANISMS.md](MECHANISMS.md)** - Documented patterns, mechanisms, and design decisions implemented in the codebase

### How to Use This Folder

1. **Before Starting**: Read ARCHITECTURE.md and IMPLEMENTATION_PLAN.md to understand the overall project structure
2. **During Development**: Reference CODING_GUIDELINES.md for consistent implementation patterns
3. **After Implementation**: Update MECHANISMS.md to document new patterns and architectural decisions
4. **Continuous**: Keep all documents synchronized with actual implementation

## For AI Agents

When working on this project:
1. Always reference the PROJECT_CONTEXT.md at the root for high-level understanding
2. Consult ARCHITECTURE.md for technical implementation details
3. Follow CODING_GUIDELINES.md for consistent code style and patterns
4. Update MECHANISMS.md when implementing new patterns or mechanisms
5. Check IMPLEMENTATION_PLAN.md to understand current project phase and priorities

## Document Maintenance

These specifications are living documents that should evolve with the project:
- Update when architectural decisions change
- Document new patterns as they emerge
- Keep implementation plan synchronized with actual progress
- Add lessons learned and gotchas for future reference
